# Translation Guide

이 가이드는 `paper-reader` 스킬이 논문을 한국어로 번역할 때 따라야 할 원칙을 정리한 것이다. **번역에 들어가기 전에 반드시 통독할 것.**

## 핵심 철학

좋은 학술 번역은 **두 언어 사이의 사전 변환이 아니라, 한 사고 체계에서 다른 사고 체계로의 이식**이다. 영어 학술 문장의 구조(긴 명사구, 수동태, 후위 수식)를 그대로 한국어로 옮기면 문장은 한국어처럼 보이지만 한국어 사용자가 읽기 어렵다. 의미를 끄집어내고, 그 의미를 한국어가 자연스럽게 풀어내는 방식으로 다시 짠다.

이 스킬의 사용자는 깊이를 최우선으로 한다. 짧고 빠르게 끝내려고 의역을 거칠게 하지 말 것. 정성껏, 한 단락씩 신중하게.

## 원칙

### 1. 의미 우선, 구조는 한국어 식으로

영어:
> Recent work on vision-language-action models has demonstrated promising results in robotic manipulation, particularly when leveraging large-scale pre-training on web-scale image-text data.

직역 (피해야 할 것):
> 비전-언어-행동 모델에 대한 최근 연구는 특히 웹 스케일 이미지-텍스트 데이터에 대한 대규모 사전 훈련을 활용할 때 로봇 매니퓰레이션에서 유망한 결과를 보여주었다.

좋은 번역:
> 최근 vision-language-action(VLA) 모델 연구는 로봇 매니퓰레이션에서 좋은 결과를 보여주고 있다. 특히 웹 규모의 이미지-텍스트 데이터로 대규모 사전학습을 거친 모델일수록 효과적이다.

영어 한 문장이 한국어 두 문장이 되어도 좋다. 핵심은 "최근 연구 → 좋은 결과 → 사전학습이 핵심"이라는 흐름이 명확하게 전달되는 것이다.

### 2. 전문 용어 표기

- **첫 등장 시**: "한글 표기(English)" 병기 — 예: "어텐션(attention)", "행렬곱(matrix multiplication)"
- **이후**: 자연스러운 쪽 선택. 한국어 표기가 어색하거나 익숙한 영어 표기가 표준이면 영어 그대로 — 예: "attention", "softmax", "transformer". 굳이 "변환기"라고 옮기지 말 것.
- **약어**: 첫 등장 시 풀어쓰고 "(VLA)" 식으로 약어 명시. 이후 약어 사용.
- **고유명사 / 모델명**: 그대로 유지. SmolVLA, π0, Llama, GPT-4 등.
- **분야 표준 영어**: 그대로 — token, embedding, fine-tune, pretrain, latent, gradient 등. "잠재"보다 "latent"가 익숙하면 latent로.

판단 기준: "이 분야 한국인 연구자가 슬랙에 쓸 때 어느 표기를 쓸까?" 그 표기를 따른다.

### 3. 수식과 심볼

수식은 그대로 보존한다. LaTeX 표기를 마크다운 안에 살린다:

- 인라인: `$x_t$`, `$p(\theta | D)$`
- 블록:
  ```
  $$
  \mathcal{L} = -\mathbb{E}_{x \sim p_{\text{data}}}[\log p_\theta(x)]
  $$
  ```

수식이 핵심 메시지를 담고 있을 때, 수식 직후에 한국어 직관 설명을 한두 문장 덧붙이면 좋다.

### 4. Figure / Table 참조

- "Figure 3", "Fig. 3", "Table 2" 같은 참조는 그대로 유지하거나 "그림 3", "표 2"로 옮긴다. 일관성만 지키면 어느 쪽이든 OK.
- Figure caption은 번역. 원문 캡션은 토글로 볼 수 있도록 데이터에 함께 둔다.

### 5. 자주 등장하는 표현 처리

| 영어 | 좋은 번역 |
|---|---|
| we propose / we introduce | 본 논문에서는 ~을 제안한다 / ~을 도입한다 |
| we show that | ~임을 보인다 |
| state-of-the-art (SOTA) | 최고 성능, SOTA |
| baseline | 기준 모델, 베이스라인 |
| ablation study | 어블레이션, 컴포넌트 제거 실험 |
| empirically | 실험적으로 |
| outperforms X by Y% | X 대비 Y% 향상 |
| in this work | 본 연구에서는 |
| It has been shown that | ~이 알려져 있다 |
| Note that | 단, ~. / 참고로 ~ |

### 6. 어색한 한국어 피하기

- "~을 통해" 남발 금지 → "~으로", "~을 사용해", "~함으로써" 등 다양화
- "~할 수 있다" 남발 금지 → 능동/수동 구분, "~된다", "~이 가능하다" 등
- "이는 ~을 의미한다" → "즉, ~이다", "다시 말해 ~이다" 등
- 영어 어순(주어-동사-목적어) 그대로 옮기지 말 것
- 무생물 주어 능동태 ("This paper proposes...") → "본 논문은 ~을 제안한다"가 자연스러우면 그대로, 어색하면 "본 논문에서는 ~을 제안한다"로

### 7. 번역하지 말 것

- 코드 블록 안의 코드: 주석만 번역
- 알고리즘 의사코드의 키워드 (`for`, `while`, `return`): 그대로
- 함수명/변수명: 그대로
- 모델명/데이터셋명/벤치마크명: 그대로 (LIBERO, ImageNet, COCO, MMLU 등)

## Reader's Notes 작성

각 주요 섹션 (Abstract, Introduction, Method 등) 끝에 "Reader's Notes" 박스를 둔다. 번역과 별개로, 읽는 사람을 위한 보충이다.

좋은 Reader's Notes는 다음 다섯 종류 중 하나를 담는다:

1. **직관 설명** — 수식이나 추상적 개념을 일상 언어로 풀어줌. 예: "이 loss는 결국 '예측이 맞으면 칭찬, 틀리면 혼냄'이고, 음수 로그라서 최소화 방향이다."

2. **역사적 맥락** — 이 아이디어가 어디서 왔는지. 예: "Flow matching은 2022년 Lipman et al.이 diffusion의 ODE 해석을 일반화하면서 나온 개념이다. 이전의 score matching 계열과의 차이는 ..."

3. **인접 연구** — 이 섹션의 아이디어를 다르게 푼 다른 논문 짧게. 예: "비슷한 동기로 출발한 RT-2(2023)는 token-level autoregression을 쓰는 반면, 본 논문은 flow matching으로 continuous action을 직접 모델링한다."

4. **구현/배포 함의** — 실무자 관점. 예: "Action expert가 별도 모듈이라는 점은 edge 배포 시 quantization을 따로 적용할 수 있다는 의미. SigLIP encoder만 INT8로 떨어뜨려도 latency가 크게 줄어든다."

5. **저자가 슬쩍 넘긴 부분** — 논문이 명시하지 않은 가정이나 한계. 예: "이 실험들은 모두 시뮬레이션이고 sim-to-real gap에 대한 논의는 없다. Appendix C에 짧게 언급되지만 본문에서는 비켜간다."

피해야 할 Reader's Notes:
- 본문 내용을 그냥 다시 풀어쓴 것 (요약 X, 보충 O)
- 일반적인 격언 ("이 분야는 빠르게 발전하고 있다" 같은 공허한 말)
- 자신 없는 추측을 단정조로 쓰기 (확실하지 않으면 "추측건대" 같은 헷지를 붙이거나 아예 안 쓰기)
- 너무 길게 (300-700자 정도가 적당. 통찰 1-3개)

길이가 부족할 것 같으면 Reader's Notes를 짧게 두거나 아예 생략하는 게 낫다 — 안 쓰는 것보다 무성의한 것이 더 나쁘다. 모든 섹션마다 Reader's Notes가 있을 필요는 없다. Method, Experiments 같은 핵심 섹션에 집중.

## 마지막 체크리스트

번역을 끝내고 다시 읽었을 때:
- [ ] 한국어 사용자가 영어 원문 없이 이 글만 읽고 핵심을 잡을 수 있나?
- [ ] 첫 등장 시 약어/용어가 제대로 풀려 있나?
- [ ] 수식이 깨지지 않았나? (`$`/`$$` 균형, escape 안 된 `\`)
- [ ] 어색한 직역체가 남아 있지 않나?
- [ ] Reader's Notes가 진짜 통찰을 담고 있나, 아니면 본문 재요약인가?
- [ ] 도메인 표준 표기를 따르고 있나? (예: "attention"이지 "주의"가 아님)
